# NanoCtrl Refactoring Documentation

- Generated by AI.

## Overview

NanoCtrl is the control plane server for NanoInfra distributed LLM inference. This document records the modularization refactoring from a monolithic single-file application to a clean, modular architecture.

## Problem Statement

The original NanoCtrl codebase had several maintainability issues:

| Problem | Details |
|---------|---------|
| **Monolithic main.rs** | 1291 lines containing all 13 HTTP handlers |
| **Repeated Redis boilerplate** | Each handler had ~10 lines of `get_multiplexed_async_connection` + error handling (13 occurrences) |
| **Repeated key prefix logic** | `if key_prefix.is_empty() { ... } else { format!("{}:...", ...) }` appeared 30+ times |
| **No unified error type** | Different handlers returned errors in inconsistent formats |
| **Embedded Lua scripts** | Large Lua script strings embedded as Rust `const &str` in source |
| **No connection pooling** | Each request created a new Redis connection |

## Solution

Modularize the codebase by extracting:
1. A unified error type (`AppError`)
2. A Redis repository layer with connection pool (`RedisRepo`)
3. Handler modules grouped by domain
4. Network utilities
5. External Lua scripts

## Implementation Details

### 1. Unified Error Type — `error.rs`

```rust
pub enum AppError {
    Redis(redis::RedisError),        // Redis connection/command errors
    NotFound(String),                // Resource not found
    Conflict(String),                // e.g. duplicate agent name
    Serialization(serde_json::Error),// JSON errors
    Internal(String),                // Catch-all
}
```

Implements `IntoResponse` for automatic HTTP error mapping:
- `Redis` / `Internal` → 500
- `NotFound` → 404
- `Conflict` → 409
- `Serialization` → 400

Handlers now use `Result<T, AppError>` with `?` propagation instead of manual error blocks.

### 2. Redis Repository — `redis_repo.rs`

Key design decisions:

- **Connection Pool**: Uses `deadpool-redis` instead of per-request `get_multiplexed_async_connection()`
- **`scoped_key()` helper**: Eliminates 30+ repeated `if key_prefix.is_empty()` blocks:
  ```rust
  // Before (repeated everywhere):
  let key = if key_prefix.is_empty() {
      format!("engine:{}", id)
  } else {
      format!("{}:engine:{}", key_prefix, id)
  };

  // After (one-liner):
  let key = repo.scoped_key(scope, &["engine", id]);
  ```
- **Lua scripts loaded from files**: Read from `lua/` directory at startup via `CARGO_MANIFEST_DIR`

### 3. Handler Modules — `handlers/`

| Module | Endpoints | Description |
|--------|-----------|-------------|
| `engine.rs` | `register_engine`, `unregister_engine`, `heartbeat_engine`, `get_engine_info`, `list_engines` | LLM engine lifecycle |
| `peer.rs` | `start_peer_agent`, `query`, `cleanup` | Peer agent management |
| `rdma.rs` | `set_desired_topology`, `register_mr`, `get_mr_info` | RDMA connection management |
| `util.rs` | `/` (health), `get_redis_address` | Utility endpoints |

### 4. Network Utilities — `net.rs`

Extracted from `main.rs`:
- `get_server_ip_for_client()` — UDP socket trick for IP detection
- `get_local_public_ip()` — Non-loopback IP detection
- `resolve_public_redis_url()` — Redis URL rewriting for remote clients
- `resolve_redis_for_client()` — Full Redis address resolution logic

### 5. External Lua Scripts — `lua/`

| Script | Purpose | Redis Operations |
|--------|---------|-----------------|
| `register_engine.lua` | Atomic engine registration | HSET + EXPIRE + INCR + PUBLISH |
| `unregister_engine.lua` | Atomic engine removal | DEL + INCR + PUBLISH |
| `heartbeat_engine.lua` | TTL refresh only | EXPIRE |

### 6. Dependencies Added

```toml
# Cargo.toml
deadpool-redis = "0.18"   # Connection pool for Redis
```
