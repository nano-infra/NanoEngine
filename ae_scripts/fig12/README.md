# Reproducing Figure 12

Figure 12 compares NanoDeploy with five vLLM baselines on six workloads. Run
all commands from the `ae_scripts` directory. Use a new `RUN_ID` for each
fresh run so that results from different runs are not mixed.

## Resource and time estimate

Reserve 4 nodes with 8 H200 GPUs per node for the full workflow.

| Stage | GPUs | Expected time |
| --- | ---: | ---: |
| NanoDeploy sweep (67 rate points) | 32 H200 GPUs | about 16 hours |
| Five vLLM baseline sweeps (345 cases) | 32 H200 GPUs | about 80 hours |

The full reproduction takes about 4 days.

## Full reproduction

The following command runs every NanoDeploy and vLLM point on four nodes and
plots the freshly generated results:

```bash
export RUN_ID=ae_run1
export NUM_NODES=4

python3 fig12/reproduce_fig12.py \
  --nodes "$NUM_NODES" \
  --run-id "$RUN_ID"
```

The script uses the complete configured rate sweeps and sends requests for 600
seconds at each rate, with a one-hour safety timeout per rate. Request-length
filtering is disabled by default. It runs NanoDeploy first, then all five vLLM
baselines, and finally generates the PDF, PNG, and metrics TSV under
`fig12/results/e2e/plots/4node/`.

## Run selected rates

For a shorter check, select a workload, one or more rates, and a shorter sending
duration:

```bash
export RUN_ID=ae_run1
export NUM_NODES=4

python3 fig12/launch_nanodeploy_e2e.py \
  --nodes "$NUM_NODES" \
  --run-id "$RUN_ID" \
  --workload dpsk_issue1 \
  --rate 30 40 \
  --bench-duration-sec 600

python3 fig12/launch_vllm_e2e.py \
  --nodes "$NUM_NODES" \
  --run-id "$RUN_ID" \
  --workload dpsk_issue1 \
  --strategy dp_least_batch dp_least_cache cp2 cp4 cp8 \
  --rate 30 40 \
  --bench-duration-sec 600
```

Pass one or more strategy names after `--strategy`. The default (omitting
`--strategy`) runs all five: `dp_least_batch`, `dp_least_cache`, `cp2`, `cp4`,
and `cp8`. The two launchers store results in separate NanoDeploy and vLLM
trees, so they can safely share the same `--run-id`.

## Plot fresh runs

`--nano-run` and `--vllm-run` take the values passed to the corresponding
launchers as `--run-id`. Reuse the same `RUN_ID` when plotting:

```bash
export RUN_ID=ae_run1
export NUM_NODES=4

python3 fig12/plot_fig12_end2end.py \
  --nodes "$NUM_NODES" \
  --nano-run "$RUN_ID" \
  --vllm-run "$RUN_ID"
```

Both launchers print `Run ID: ae_run1` near startup. NanoDeploy stores the ID
under `fig12/results/e2e/nanodeploy/4node/`; vLLM records it in the case CSV
name under `fig12/results/e2e/vllm/4node/_case_csv/`.

To plot one system, omit the other run argument. The plotter only consumes
results generated by the launchers above.
