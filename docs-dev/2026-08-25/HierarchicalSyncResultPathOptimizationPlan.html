Hierarchical sync result-path optimization plan

在不引入 async/depth-2、不改变 worker 协议和调度语义的前提下，消除 LocalScheduler.postprocess() 的重复 request/rank 映射与 SP × batch Python 遍历，并让 LocalExecutor 复用 plan 阶段已经冻结的顺序信息。

最小设计

plan 阶段一次冻结

在 LocalScheduler.plan_decode() 的单次 sequence 遍历中，同时构建： 

frozen_mastered_sequences: dict[int, tuple[Sequence, ...]]
frozen_real_row_indices: dict[int, tuple[int, ...]]
frozen_request_order: dict[int, tuple[int, ...]]
request_master_global_rank: dict[int, int]

frozen_real_row_indices[rank] 指向 worker 原始 token_rows 中的真实请求行；control dummy 行不进入 WorkerDecodeResult.sampled_token_ids。

Executor 直接复用冻结映射

  • 提交前直接读取 frozen_mastered_sequences，不再调用每个 Sequence 的 block_ctx() 做 rank 过滤。
  • 结果路径按 frozen_real_row_indices 从 token_rows positional pack。
  • 继续校验 result envelope、row count、wave/quantum/rank、每行 token count。
  • 保留旧 dict/set 路径作为显式诊断回退，但 production/config/benchmark 默认启用 fastpath。

Scheduler 按 rank 单次重建

batch.validate_worker_results() 已保证返回 token 顺序等于 frozen_request_order。postprocess 对每个 rank 只遍历其 frozen_mastered_sequences： 

real_tokens = iter(result.sampled_token_ids)
for sequence in frozen_mastered_sequences[rank]:
    if is_control_dummy(sequence):
        append(sequence, ZERO_DUMMY_TOKENS)
    else:
        tokens = next(real_tokens)  # aborted request 也必须消费
        if sequence.seq_id not in aborted_ids:
            append(sequence, tokens)

这样保留 C++ postprocess 期望的 mastered Sequence 顺序，同时把 SP × batch 降为所有 mastered rows 的一次总遍历。

Review 决定：两个 frozen rank map 是 LocalDecodeBatch 的必填字段，不提供静默回退扫描。 这样任何非 LocalScheduler 构造的 batch 都必须显式证明顺序不变量；现有手工构造测试将同步更新。

必须保持的正确性不变量

身份与顺序

  • batch 只属于一个 engine/wave/quantum。
  • 每个 global rank 恰好一个 WorkerDecodeResult。
  • result request IDs 必须严格等于冻结顺序。
  • 每个真实请求恰好 16 个 sampled token。

dummy 与 abort

  • dummy 依赖 Python 对象身份，不依赖可能碰撞的 seq_id。
  • inflight abort 不提交 worker 返回 token。
  • 即使 abort，仍消费对应 positional token，防止后续请求错位。
  • dummy 继续向 C++ postprocess 注入 16 个零 token。

状态与资源

  • num_completed_tokens、ITL slots、mastered tokens 统计不变。
  • FirstTokenEvent/FinishEvent 的顺序和 generated_count 不变。
  • preemption/readmission 和 terminal 去重不变。

Positional 假设

Worker 的 token rows 必须保持 RDMA 反序列化 Sequence 的 mastered 顺序。当前 slow path 的 “request-id 校验”同样由 driver 侧 Sequence 推导，并不能检测 worker 静默重排行，因此启用 positional path 不会移除一项真实存在的端到端校验。

若 review 发现 worker 任一路径可能重排 mastered rows，计划必须先扩展 worker result identity，不能直接默认 fastpath。

测试顺序与验收门槛

  1. 原始代码 characterization：先增加多 rank、多真实请求、control dummy、倒序 worker results、inflight abort 的 token 对应测试，并确认原实现通过。
  2. 结构回归：优化后用禁止遍历的 guard list 证明 postprocess 不再迭代 batch._all_sequences；用会在 block_ctx() 上失败的 fake Sequence 证明 Executor 不再提交前扫描。
  3. 错误路径：缺 rank、重复 rank、错误 wave/quantum、错误 row count、错误 token count 均保持 fail-stop。
  4. CPU 回归：运行 hierarchical contract/control-plane、Ray executor diagnostics 和 ingress 相关测试；不触发 GPU benchmark。
  5. GPU 验收（后续单独授权）：同 commit、qdiag off 的 DP2SP8 交错 A/B；再用一个 qdiag probe 对比 submit/postprocess 直接计时。
门槛要求
行为完成请求、逐请求 output token count、abort/terminal 事件完全一致。
结构postprocess 不再执行 SP × batch._all_sequences；submit 不再重新计算 mastered rows。
直接计时postprocess 与 actor-submit 中至少一个稳定下降；无阶段显著退化。
端到端只把重复配对且超过运行方差的改善认定为收益。

第二轮 Review 记录

结论：设计可进入 characterization 阶段；不需要扩大到 worker 协议或 C++。

检查项结论计划修订
Worker row 顺序 安全。server 序列化 canonical list；worker 用稳定 list comprehension 过滤 mastered Sequence；最终 token tensor 行顺序保持该 sp_seqs 顺序。 增加 positional mapping characterization test。
旧 slow-path 校验强度 旧 actual_request_order 也由 driver 侧 mastered Sequence 推导，无法检测 worker 静默重排；fastpath 不会删除真实 worker identity 校验。 默认启用 fastpath，保留显式回退用于 A/B。
Inflight abort 安全但易错。abort 后 Sequence 会被 deallocate；positional iterator 必须先消费该真实请求 token，再跳过 C++ postprocess 输入。 增加同 rank 中“aborted request 位于 surviving requests 之间”的测试。
Control dummy ID 碰撞 必须继续按 Python 对象身份识别，不能按 seq_id。 冻结 mastered rows 保存原对象；保留 object-id set。
现有 fastpath 收益 历史实测只节省 0.087 ms/engine-quantum，不能解释 2.56 ms postprocess 差值。 验收重点放在 Scheduler 线性重建和 Executor submit 扫描，不夸大 result pack 收益。
recv_seqs 平均值受 worker 启动与 RDMA 到达相位影响，不能作为本修改的直接验收指标。 只看 executor begin→result、actor submit、postprocess 以及端到端配对。
手工 batch / ZMQ LocalDecodeBatch 只有 production builder 和少量测试直接构造；ZMQ 与 Ray 都进入同一 result rebuild。 frozen fields 设为必填；更新 Ray/ZMQ fake batch 测试。
Config 默认值 benchmark 当前用环境变量默认 0 覆盖 Config；只改 Config 不会生效。 Config 与 benchmark env fallback 同时改为启用。

Review 后的额外收敛

  • postprocess 复用 batch.request_master_global_rank，不再从 live Sequence 重建 master_sp_by_request。
  • 只计算一次 surviving inflight request 顺序，复用到完成计数和 terminal 状态更新。
  • 保留 validate_worker_results() 的小型 rank map，以支持倒序返回和 duplicate/missing/extra rank fail-stop；不为 8 个 rank 牺牲清晰性。
  • per_rank_sequences 的完整 canonical payload 不在本计划内，避免改变 worker 输入语义。
  • 不触碰用户已有的 .gitignore 与 AGENTS.md 修改。
